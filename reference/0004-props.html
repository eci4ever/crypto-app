Props — sending typed data between components

Props are the arguments a parent passes to a child component. Data flows one way only: down.

Reading a component that takes props

interface CoinTableProps {
  coins: CoinMarket[]   // array of coin objects
  currency: string
}

export default function CoinTable({ coins, currency }: CoinTableProps) {
  // coins and currency are now variables, guaranteed typed
}

The { coins, currency } in the parameter list is destructuring — pulling named fields out of the props object.

Passing props (the parent side)

<CoinTable coins={coins} currency={currency} />

Looks like an HTML attribute, but the braces make it a JavaScript value — the same {} rule from Lesson 2.

color = '#34d399' is a default parameter: if the parent doesn't pass color, it falls back to green. The prop is technically still required-safe because it always has a value.

Rules of props

  • Read-only in the child. A child can never change its props. To change something, the parent re-renders with a new value.
  • Flow down. App → pages → components. Children don't reach up; they ask parents to change things via callbacks passed as props (e.g. onClick).
  • Typed. Pass the wrong type and tsc fails at build time — the same safety net as Lesson 3.
