JSX — writing markup inside TypeScript

A React component is a function that returns markup. That markup is JSX: HTML-like syntax that runs inside a .tsx file and gets compiled to plain JavaScript at build time.

The three rules

  1. Return one root element — wrap siblings in a <div> or an empty fragment <>…</>.
  2. Close every tag — <br />, <img />, never <br>.
  3. Use camelCase attributes — className (not class), onClick (not onclick), htmlFor.

Curly braces escape into JavaScript

// display a variable
<p>Price: {price}</p>

// run a function call
<td>{formatPrice(coin.current_price, currency)}</td>

// attributes can use braces too
<img src={coin.image} width={24} />

Anything between {} is a real JavaScript expression — numbers, strings, function calls, ternaries, even className={condition ? 'a' : 'b'}.

Conditional rendering

{has ? '♥' : '♡'}                          // pick one of two
{isLoading && <p>Loading…</p>}            // render only if true
{condition ? (<A />) : (<B />)}         // pick between elements

No special syntax — just normal JavaScript operators inside braces.

Rendering lists

{coins.map((coin) => (
  <tr key={coin.id}>…</tr>
))}
  • .map() turns an array into an array of elements.
  • key is required on each item — React uses it to track items as the list changes. Use a stable id, never the array index if the list reorders.
