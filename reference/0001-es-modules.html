ES Modules — the glue of src/

Every file in src/ is a module. Modules export things they want to share and import things they need. That web of imports is how a 50-file app holds together.

Export — giving things away

// src/utils/format.ts
export function formatPrice(price: number, code: string): string {
  // ...
}

export const CURRENCIES = ['usd', 'myr']

Default export — one main thing

// src/pages/ListPage.tsx
export default function ListPage() {
  // ...
}

Many components use export default for the component itself.

Import — taking things in

// Named imports — must match the exported name
import { formatPrice } from '../utils/format.ts'
import { useSettings } from '../stores/settings.ts'

// Default import — you can name it anything
import ListPage from '../pages/ListPage.tsx'

Relative paths

./name        // same folder
../name       // one folder up
../../name    // two folders up

Here src/pages/ListPage.tsx imports ../components/CoinTable.tsx — up out of pages, into components.

import type — types only

import type { CoinMarket } from '../services/types.ts'

This repo's tsconfig.json sets verbatimModuleSyntax: true, so types MUST use import type. It gets erased at build time — zero runtime cost.

Rules of thumb

  • One direction only — files import from inside src; index.html only ever loads main.tsx.
  • A component is a function. If a file's only job is one component, it export defaults it.
  • Utilities are shared pieces — they use named exports so many files can pick what they need.
  • Circular imports (A imports B, B imports A) are a smell — avoid them.
