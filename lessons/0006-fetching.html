Data fetching — reaching outside the component

Every price on your screen arrives from a server in Malaysia or worldwide — by a network call. This lesson is the whole journey: component → hook → fetch → CoinGecko → back to the table.

Tied to your mission The single most common thing you'll maintain in this app is a data call: a new endpoint, a changed field, an error state. If you can read one useQuery, you can read them all — there are exactly four in this repo.

Why fetching is special

So far every component has been pure: props in, JSX out, no surprises. Fetching breaks that — it's an async side effect that can take 200ms or fail entirely. You don't want that logic tangled inside the JSX. The repo's answer: wrap it in a hook, and let a library manage the mess.

Read one hook, read them all

Open src/hooks/useMarket.ts — the smallest and most used:

export function useMarket(currency: string) {
  return useQuery({
    queryKey: ['market', currency],
    queryFn: () => fetchMarket(currency),
    refetchInterval: 60_000,
    staleTime: 30_000,
  })
}

Four options, four questions answered:

  • queryKey — "what are we fetching, exactly?" ['market', currency]. Change currency, get a different cache. This is why switching the navbar dropdown swaps the whole table's prices without reloading.
  • queryFn — "how do we fetch it?" A function that must return the data (async counts).
  • refetchInterval — "how often do we refresh?" 60_000 ms — the "refreshed every 60s" in your Lesson 2 subtitle.
  • staleTime — "how old may cached data be before we bother?" 30 seconds. Stay inside CoinGecko's rate limits without going stale.

That 6-line hook is a self-contained feature. This is the maintainer's mental model: one hook = one data concern.

What the hook hands back

Now the consumer. In src/pages/ListPage.tsx:

const { data, isLoading, isError } = useMarket(currency)

And the page branches on them — you saw these three states already without knowing it:

{isLoading && <div>Loading market data…</div>}
{isError   && <div>Failed to load market data…</div>}
{!isLoading && !isError && <CoinTable coins={coins} currency={currency} />}

data is typed: because fetchMarket returns Promise<CoinMarket[]>, data is a CoinMarket[] and every field you touch is checked. One wrong field name = tsc error, not a broken table at 2am.

Under the hook: fetch + Promise

Hooks never touch the network themselves — they call the service layer. Open src/services/coingecko.ts:

export async function fetchMarket(currency: string, perPage = 50): Promise<CoinMarket[]> {
  const params = new URLSearchParams({ vs_currency: currency, ... })
  const res = await fetch(`${BASE_URL}/coins/markets?${params}`)
  if (!res.ok) throw new Error(`CoinGecko request failed: ${res.status}`)
  return (await res.json()) as CoinMarket[]
}

Three async concepts, and that's your whole toolkit for a while:

  • async — this function returns a Promise (a "later, maybe" value).
  • await — pause right here until the network answers, then use the value. Code reads top-to-bottom despite the wait.
  • as CoinMarket[] — a type assertion. JSON from the wild has no types; we promise it matches our interface. This is the one place a hand-written claim is OK — at the door where data enters the app.

Notice the error line: throw new Error(...). That's how isError becomes true — the query catches the thrown error and flips the flag.

Your edit — the skill

Give the user a manual Refresh button — a real feature, and it exercises the hook's return values you just learned.

  1. In src/pages/ListPage.tsx line 15, add two more values:
const { data, isLoading, isError, refetch, isFetching } = useMarket(currency)
  1. In the header, next to the search/filter controls, add:
<button
  type="button"
  onClick={() => refetch()}
  disabled={isFetching}
  className="rounded-md border border-slate-700 px-3 py-2 text-sm text-slate-200 transition-colors hover:bg-slate-800 disabled:opacity-50"
>
  {isFetching ? 'Refreshing…' : 'Refresh'}
</button>
  1. Save. Click Refresh — it shows "Refreshing…" then updates. Watch the network tab in DevTools to see the request hit CoinGecko.
  2. Notice it doesn't flash a loading screen: refetch is a background refresh — isFetching is true, isLoading stays false because data already exists.

You just added a feature by consuming three return values of a hook. That's maintenance.
