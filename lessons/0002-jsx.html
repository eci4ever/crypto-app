JSX — writing HTML inside TypeScript

You saw <App /> in Lesson 1 and read it as "render App here." This lesson explains why that line is even legal — and why the files are called .tsx, not .ts.

Tied to your mission Nearly every file you'll maintain in this repo is JSX: the Navbar line you edited, the table rows, the heart button. Get the three rules below and the code stops looking like magic.

A component is a function that returns markup

Open src/components/WatchlistButton.tsx. Strip the imports and state, and what remains is the whole trick:

export function WatchlistButton({ id }) {
  // ...state logic...
  return (
    <button onClick={() => toggle(id)}>
      {has ? '♥' : '♡'}
    </button>
  )
}

JSX is the return (…) part. It's not HTML, and it's not a string — it's markup that the Vite build tool compiles into JavaScript instructions for React. Write it like HTML, and React turns it into actual page elements.

Why .tsx? Because a file containing JSX must use the .tsx extension so the compiler knows to expect markup inside the TypeScript.

Rule 1 — className, not class

JSX isn't HTML, so it doesn't reuse HTML attribute names. The attribute you know as class becomes className. All attributes are camelCase: onClick, aria-label stays hyphenated but others change.

You've already used this: every className="rounded-md px-4…" in this repo is Tailwind class names handed to the className attribute.

Rule 2 — curly braces {} escape into JavaScript

JSX has two modes:

  • Markup mode — anything written plainly is literal text.
  • Expression mode — anything inside {} is real TypeScript.
<p>Price: {formatPrice(coin.current_price, currency)}</p>
<button onClick={() => toggle(id)}>…</button>

Both lines are from your repo (CoinTable and WatchlistButton). The braces let you compute anything at render time. This is why the same code shows different prices each refresh — the function runs fresh on every render.

The one-liner to remember In JSX, braces {} are the door between the visual world and the code world. No braces → literal text. Braces → run this code.

Rule 3 — one root element

A component must return exactly one top-level element. When you need siblings, wrap them — or use an empty fragment:

return (
  <>
    <h1>Hello</h1>
    <p>World</p>
  </>
)

The <>…</> fragment renders nothing itself — it just groups so the rule holds.

Lists: .map() + key

How does one row become fifty? CoinTable.tsx maps over the coins array and returns a row per item:

{coins.map((coin) => (
  <tr key={coin.id}>
    <td>{coin.market_cap_rank}</td>
    <td>{formatPrice(coin.current_price, currency)}</td>
  </tr>
))}

key matters. React uses it to tell rows apart when the list changes (sorting, filtering, refreshing). Use a stable id — here coin.id, not the loop index.

Your edit — the skill

Make the list page tell the truth about what it shows. In src/pages/ListPage.tsx, find this line:

<p className="mt-1 text-sm text-slate-400">
  Top 50 coins by market cap · refreshed every 60s
</p>

Change it to use a live expression — the coins variable is already computed above in that same file:

<p className="mt-1 text-sm text-slate-400">
  Showing {coins.length} coins · refreshed every 60s
</p>
  1. Save and watch HMR update it instantly.
  2. Type "bit" in the search box — the count now shrinks as you filter.
  3. That's braces in action: the number is not hardcoded, it's computed every render.
