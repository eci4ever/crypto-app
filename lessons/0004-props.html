Props — sending typed data between components

Lesson 2 made you read <App />. This lesson makes you read <CoinTable coins={coins} currency={currency} /> — the moment a component stops being a drawing and becomes a function with arguments.

Tied to your mission Almost every maintenance task starts with a prop: adding a column to the table, colouring a chart, passing a value down. Props are where JSX meets types — the two lessons you just did, fused.

Props are function arguments

You know what a function parameter is:

function formatPrice(price, code) { … }   // parameters
formatPrice(100, 'usd')                      // arguments!

A component is exactly that function — the JSX attributes are its arguments. The parent says "here's your data," the child receives it, read-only.

Open src/pages/ListPage.tsx; near the bottom the table is used like this:

<CoinTable coins={coins} currency={currency} />

And open src/components/CoinTable.tsx; its first lines receive them:

interface CoinTableProps {
  coins: CoinMarket[]
  currency: string
}

export default function CoinTable({ coins, currency }: CoinTableProps) {
  • interface CoinTableProps — the contract (Lesson 3): "whoever renders CoinTable must give me a coin array and a currency string."
  • { coins, currency } — destructuring in the parameter list. It pulls those two fields out of the props object so you can use them as plain variables below.
  • : CoinTableProps — type it, and every call site is checked. Pass currency={42} and tsc slaps you before the browser does.

One way, top-down

Data flows down only: App renders the pages, the pages fetch and filter, then hand the results down to CoinTable, which hands shape data to Sparkline. A child never browses up to find its own data — it only sees what it's given.

That's why WatchlistButton only takes an id:

export function WatchlistButton({ id }: WatchlistButtonProps) {

It doesn't need the whole coin — a single string is the whole contract.

The key rule Props are read-only. If a child wants something to change, it calls a function it received as a prop (like onClick={() => toggle(id)}) and lets the parent re-render with new props. Change flows up; data flows down.

Defaults — a prop that always has a value

Open src/components/PriceChart.tsx:

export function PriceChart({ prices, color = '#34d399' }: PriceChartProps) {

color = '#34d399' is a default parameter. If the parent doesn't pass color, the chart draws emerald green. It's a prop a caller can omit — but the child never sees undefined.
