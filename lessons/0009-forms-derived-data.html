Forms and derived data — from text to profit

The portfolio form starts with strings, turns them into safe numbers, stores a position, and calculates what that position is worth today.

Tied to your mission Forms sit at the boundary between a person and your TypeScript code. Learning to parse and validate their values lets you add settings, filters, and data-entry features safely.

Controlled inputs keep draft state

Open src/pages/PortfolioPage.tsx. Each input receives its value from React state and writes changes back into that state:

const [amount, setAmount] = useState('')

<input
  type="number"
  value={amount}
  onChange={(e) => setAmount(e.target.value)}
/>

This is a controlled input. React state is the source of truth for what appears in the box. React requires a controlled input's onChange handler to update its backing value (React input reference).

Notice that amount is a string, even though the input has type="number". Browser input values are strings. Keeping the draft as a string also allows the box to be empty.

Submission is a boundary

function handleSubmit(e: FormEvent) {
  e.preventDefault()
  const amountNum = Number(amount)
  const priceNum = Number(buyPrice)

  if (!selectedCoin || !Number.isFinite(amountNum) ||
      !Number.isFinite(priceNum) || amountNum <= 0) {
    return
  }

  add({
    id: selectedCoin.id,
    amount: amountNum,
    buyPrice: priceNum,
    // ...
  })
}
  1. preventDefault() stops the browser's normal form navigation and page reload (React form submission guide).
  2. Number(...) converts both draft strings into numbers.
  3. The if rejects invalid data with an early return.
  4. add receives a typed Position, not raw form strings.

Stored data and derived data are different

The portfolio store saves facts entered by the user: coin, amount, and buy price. It does not save profit.

const currentValue = p.amount * price
const costBasis = p.amount * p.buyPrice
const profit = currentValue - costBasis
const profitPercent = costBasis > 0
  ? (profit / costBasis) * 100
  : 0

These values are derived data: values calculated from existing state and the latest market price. Recalculating them avoids stale data. When a coin price changes, profit changes automatically without rewriting the saved position.

Why useMemo appears here

const rows = useMemo(
  () => positions.map(/* calculate each row */),
  [positions, pricesUsd],
)

React reuses the previous result until positions or pricesUsd changes. Those values form the dependency array. useMemo caches a calculation between re-renders as an optimization; the calculation must not depend on it for correctness (React useMemo reference).

Your edit — reject a zero buy price

The form currently rejects a non-positive amount, but it still accepts a buy price of zero. Add the matching validation in handleSubmit:

if (
  !selectedCoin ||
  !Number.isFinite(amountNum) ||
  !Number.isFinite(priceNum) ||
  amountNum <= 0 ||
  priceNum <= 0
) {
  return
}

Then run npm run build. Try to explain why the check belongs after conversion and before add.

Small trap HTML attributes such as min="0" help the browser UI, but your submit handler must still protect the application boundary. UI hints are not a replacement for validation.

Trace one submission

  1. The user types "2" and "30000"; both drafts are strings.
  2. Submit prevents a page reload.
  3. The strings become the numbers 2 and 30000.
  4. Validation permits the numbers and add updates the persisted store.
  5. The component re-renders; rows derives cost, value, and profit.
