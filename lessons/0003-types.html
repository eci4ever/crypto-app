Types — TypeScript's safety net

In Lesson 2 you wrote markup. This lesson is about the other half of .tsx — the types that check your work before a browser ever sees it.

Tied to your mission To maintain this repo you'll read more types than you write. The very first file in your manual — src/services/types.ts — is just a pile of interfaces. After this lesson, that file stops being alphabet soup.

What a type is

A type is a description of data's shape. TypeScript reads every file, checks that shapes match everywhere, and refuses to build if they don't. The check happens before the code runs — in your editor (red squiggles) and when you type npm run build.

Why this matters for you JavaScript only discovers "I passed the wrong thing" at runtime, when the user's on the page. TypeScript discovers it at build time, when you're still sitting in the editor. That's the entire trade: a two-second tsc run instead of a broken site in production.

The three primitives you'll meet daily

string    // text:  "bitcoin", "usd"
number    // any:   64_234, 0.0000012, -3.2
boolean   // flags: true, false

They appear all over src/utils/format.ts. Look at the very first function you read nine lessons from now would be this:

export function currencySymbol(code: string): string {
  return CURRENCY_SYMBOLS[code.toLowerCase()] ?? `${code.toUpperCase()} `
}

Decode it: "currencySymbol takes a string named code, and returns a string." The : string after the ) is the return type — the shape guaranteed to come out.

Describing whole objects — interfaces

Numbers and strings describe single values. A coin is a whole object with many fields, so it needs an interface. Open src/services/types.ts:

export interface CoinMarket {
  id: string
  symbol: string
  name: string
  current_price: number
  price_change_percentage_24h: number
  sparkline_in_7d: { price: number[] } | null
}

Read it as a contract: "anything claiming to be a CoinMarket must have these fields, and each field must be this type."

  • number[] — an array of numbers (the 7-day sparkline points).
  • | null — "this field may also be empty." The | means or; it's called a union. Some coins don't report a sparkline, so the type admits null as an option.

That's why CoinTable.tsx guards with coin.sparkline_in_7d?.price ?? [] before drawing — the types told you it might be null, so the code handles it.

Inference — the types you don't write

Most of the time TypeScript guesses for you, from the value on the right:

const count = 50        // TS infers: number
const greeting = "hi"   // TS infers: string

You write annotations where inference can't reach: function parameters and return types. Everything else, let it infer.

How the safety net catches you — the skill

Try the muscle memory of reading and fixing a type error. This is the single most common task in day-to-day maintenance.

  1. Open src/utils/format.ts.
  2. Change formatPrice(price: number, code: string) so code is a number: code: number.
  3. Save. Watch your editor draw red squiggles.
  4. Run npm run build. tsc will list every call site in the whole app that passes a string to code — with file, line, and column.
  5. Read one of the errors. It names the file, the line, and the mismatch (string vs number).
  6. Now undo the change (code: string again) and rebuild until clean.

That experiment was the lesson: a type is contagious. Change one signature and tsc hands you the complete repair list — including the call sites you'd never have remembered.
