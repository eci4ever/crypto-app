The Repo Map — how this code becomes a web page

Before TypeScript or React syntax, you need one mental model: where things live, and how the code flows. Build that model today by tracing your own app from first byte to finished page.

Tied to your mission You want to maintain this repo. You cannot fix what you cannot find. This lesson gives you the map — everything else (types, props, state) drops onto the map in later lessons.

Follow the trail

The browser never reads src/ directly. It reads one HTML file, which pulls in JavaScript, which draws the page. The whole app is a pipeline:

index.html — the single entry point the browser loads
loads script
main.tsx — imports CSS, creates the React root
renders
App.tsx — the top of the component tree; owns routing
switches between
pages / components — the UI you see (Navbar, CoinTable, …)

The entry point: index.html

Open index.html at the repo root. It's almost empty — deliberately. The two lines that matter:

<div id="app"></div>
<script type="module" src="/src/main.tsx"></script>
  • <div id="app"> is an empty mount point — a blank slot in the page.
  • The script tag is the only JavaScript entry. Everything else hangs off it.

That's the whole trick of a single-page app: one HTML file, one empty div, one script — and React builds everything else.

Mounting: main.tsx

Now open src/main.tsx. Four lines do the real work:

const queryClient = new QueryClient({ ... })

const root = document.getElementById('app')!
createRoot(root).render(
  <QueryClientProvider client={queryClient}>
    <App />
  </QueryClientProvider>,
)

document.getElementById('app')! grabs that empty div. createRoot(...).render(...) tells React: draw <App /> here. The ! (non-null assertion) says "I promise this element exists." QueryClientProvider just hands data-fetching powers to everything below.

Note That's your first JSX — HTML-like syntax written inside a TypeScript file. You'll study it properly next lesson; for now, read <App /> as "render the App component here."

The tree: App.tsx

Open src/App.tsx. It renders a Navbar and then a Switch — a router that decides which page to show based on the URL:

<Route path="/" component={ListPage} />
<Route path="/coin/:id" component={CoinPage} />
<Route path="/converter" component={ConverterPage} />
<Route path="/portfolio" component={PortfolioPage} />

Read the URL bar while you click around the app: /coin/bitcoin means CoinPage, showing bitcoin. Routing is just URL → which component to draw.

The glue: imports and exports

Notice how every file above imports the others. main.tsx imports App; App.tsx imports the pages; the pages import components, stores, and services. This import graph is the repo map.

TypeScript files live in their folders for a reason — pages are screens, components are reusable pieces, stores are shared data, services talk to CoinGecko, utils are pure helpers. Whenever you're lost, the folder name tells you the file's job.

The dev loop: why edits appear instantly

Run npm run dev and open http://localhost:5173. The dev server watches your files. When you save, Hot Module Replacement (HMR) swaps in just the changed piece — no full reload, your app state survives. This is the tightest feedback loop in programming, and it's your best teacher.

Your first edit — the skill

  1. Keep npm run dev running in one terminal.
  2. Open src/components/Navbar.tsx.
  3. Find the brand line: <span className="text-emerald-400">₿</span> Crypto App.
  4. Change Crypto App to something personal — your name, your wallet, anything.
  5. Save. Look at the browser. That was HMR, and that was your first edit to this codebase.
